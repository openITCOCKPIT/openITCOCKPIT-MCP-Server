# Baseline: current tool surface, 2026-09-16

Commit `dbeeb33`, all 39 tools registered (write tools on, `toolsets=all`),
40 cases, 5 samples per case, neutral system prompt (`evals/run.py`).

## Coverage

23 of 40 operator tasks have a tool on this surface. The other 17 - maintenance
windows, acknowledging, rechecking, finding noise, explaining a missing
notification, impact before a change, applying configuration, availability,
forecasts, listing hosts that are down, and a cause/symptom overview - have none.

## Tasks without a tool

Asked anyway, the models called something unrelated: `get_host_info` (Qwen 16,
DeepSeek 36 of 85), `list_services_by_state`, `list_log_entries`,
`list_host_downtimes`. Qwen invented tool names three times (`delete_host`,
`update_config`, `apply_config`); DeepSeek never did.

## Reading these numbers

- Only the first call is scored. DeepSeek's misses are mostly a sensible look-up
  before acting (`get_container_tree` before `create_host`, `get_host_info`
  before `update_host`). Several tasks that need more than one step are
  therefore under-counted for the more careful model.
- Every tool definition is sent with every request: the 39 cost about 10,700
  prompt tokens on both models (see `docs/tool-design.md`).
